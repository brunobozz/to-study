Teoria: Mocking em Testes Unitários

O teste unitário foca em validar uma unidade de código isolada (ex: uma classe de serviço) sem acionar suas dependências reais (como bancos de dados ou chamadas HTTP de rede).

Para simular dependências e monitorar chamadas de métodos, criamos **Mocks** ou **Spies**:

  • SpyObj / spyOn (Jasmine) ou jest.fn() (Jest): Permite interceptar execuções de métodos das dependências e mockar os retornos (síncronos ou assíncronos via Observables/Promises).
  • Fornecimento no TestBed: Injetamos o mock no container de DI do Angular através do token {{ '{' }} provide: ServicoReal, useValue: servicoMockado {{ '}' }}.
Nota Sênior

Evite importar o HttpClientModule real em seus testes unitários. Em vez disso, use o HttpClientTestingModule (que fornece o HttpTestingController para interceptar e mockar chamadas) ou mocke o HttpClient diretamente usando spies.
