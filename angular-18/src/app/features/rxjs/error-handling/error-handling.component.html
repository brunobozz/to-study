Teoria: Resiliência com RxJS

Em aplicações reais, requisições HTTP podem falhar temporariamente devido a oscilações de rede. O RxJS oferece operadores integrados e eficientes para tratar erros de forma reativa e manter a resiliência do sistema.

  • retry(n): Assina novamente o Observable fonte até n vezes adicionais caso ele emita um erro, permitindo re-executar requisições instáveis antes de desistir.
  • catchError(fn): Intercepta falhas definitivas no fluxo de dados, permitindo retornar um Observable alternativo de fallback seguro (evitando que o fluxo quebre de vez).
Ordem dos Operadores

O operador retry deve ser posicionado antes do catchError. Dessa forma, as retentativas rodam primeiro e, caso todas falhem, o catchError intercepta a falha final.
